# 15.01 Maquettes de l'interface

## Objet

Ce document propose une maquette de chaque écran de la V1, dans le style retenu par la story [[socle-8]] : [WebTUI](https://webtui.ironclad.sh/), thème Catppuccin Latte (clair) ou Mocha (sombre), police Cascadia Code et icônes Nerd Fonts ([[43.01 Aperçu de l'interface]]). Les données sont fictives (domaines `.test`, adresses de documentation de la RFC 5737).

Les maquettes servent de référence aux stories d'interface : elles fixent l'organisation des écrans et les informations affichées, pas le détail du code. Un écart entre une maquette et le cahier des charges se tranche en faveur du CDC, puis la maquette est corrigée.

## Sources et régénération

Les maquettes sont des pages HTML statiques, dans `sources/` :

- `maquettes.css` imite WebTUI et les palettes Catppuccin, sans dépendre de `frontend/node_modules` ;
- `maquettes.js` ajoute à chaque page l'en-tête, le menu du test, le pied de page et les icônes ;
- `NN-nom.html` contient le seul contenu de l'écran `NN` ; `?theme=clair` ou `?theme=sombre` force le thème ;
- `capturer.mjs` produit les captures de ce document : `node capturer.mjs` depuis `sources/`, avec Chromium (par défaut dans `%LOCALAPPDATA%\Chromium\Application`) et Node 22 ou plus, sans paquet npm.

L'affichage suppose la police CaskaydiaCove Nerd Font (Cascadia Code complétée des glyphes Nerd Fonts) installée sur le poste ; la SPA, elle, sert ses propres polices.

Les pastilles roses numérotées des captures renvoient aux remarques numérotées de chaque écran.

## Principes

- **Navigation à deux niveaux** : l'en-tête garde la navigation générale (tests, organisations, entreprise, administration, notifications, compte) ; dans un test, un menu latéral regroupe ses sections par étape — *Préparer* (engagement, périmètre), *Tester* (déroulement, exécutions, vulnérabilités, documents), *Restituer* (résultats, export), *Suivre* (équipe et partage, historique) — avec un compteur par section.
- **Bandeau du test** : fil d'Ariane, référence et titre, statut, type et exposition, risque global et dates prévues, identiques sur toutes les sections.
- **Coffre** : l'en-tête indique si la clé privée est déverrouillée dans le Worker crypto et permet de la verrouiller ([[13.04 Protection de la clé privée contre le XSS]]).
- **Contenu chiffré** : un cadenas signale ce qui est chiffré dans le navigateur ; un contenu visible mais pas encore déchiffrable est marqué « Partage demandé ».
- **Couleurs de sévérité** : rouge (critique, P1), pêche (majeur, P2), jaune (important, P3), vert (mineur), gris (aucun, P4), toujours accompagnées d'un texte. Sur Latte, le texte des badges clairs est foncé, pour rester au-dessus de 4,5:1 ([[13.07 Licence, langues et accessibilité]]).
- **Graphiques** : barres en caractères pleins (█ et ░), dans l'esprit d'une interface en mode texte ; les graphiques exportés dans les rapports restent à définir.
- **Formulaires** : un champ par ligne sous son libellé, comme dans la SPA actuelle ; les choix fermés courts (métriques CVSS, statut de remédiation) deviennent des boutons segmentés.

## Points à trancher

- **Largeur** : la SPA limite le contenu à 100 caractères (`main { max-width: 100ch }`) ; le menu latéral et les écrans denses (déroulement, synthèse) demandent la pleine largeur dans un test.
- **Colonnes par statut** (écran 05) : le glisser-déposer doit avoir un équivalent au clavier (menu « Changer le statut »), à prévoir pour [[exploitation-7]].
- **Justification de la surcharge de priorité** (écran 10) : ajoutée par la maquette ; à reporter dans [[11.09 Vulnérabilités et remédiation]] si elle est retenue.
- **Affichage sur smartphone** : hors maquettes, reporté en V2 ([[exploitation-8]]).

## 02 Synthèse d'un test
