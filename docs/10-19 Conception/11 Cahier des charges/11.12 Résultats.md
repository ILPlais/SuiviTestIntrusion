# 11.12 Résultats

Cette partie alimente le **tableau de bord** du test et les chapitres de synthèse des rapports exportés. Les indicateurs sont calculés à partir des vulnérabilités **non clôturées** (statut de remédiation différent de **Vérifié**), sauf mention contraire.

## Risque global

Le risque global d'un test est présenté sous trois formes complémentaires, toutes visibles sur le tableau de bord :

1. **Score de gravité technique (titre)** : le **maximum** des scores CVSS de base des vulnérabilités ouvertes, affiché avec le niveau associé (Aucun → Critique, voir [[11.10 Cotation CVSS#Échelle de risque|Échelle de risque]]). C'est l'indicateur principal du bandeau d'en-tête. Pour un test mixte, voir *Test mixte v3.1 / v4.0* ci-dessous.
2. **Score agrégé optionnel** : moyenne arithmétique des scores CVSS de base, **pondérée** par la priorité de correction
	1. $P1 = 4$
	2. $P2 = 3$
	3. $P3 = 2$
	4. $P4 = 1$
	- Affiché à titre informatif, jamais à la place du maximum.
	- Pour un test mixte, une moyenne est calculée par version (voir ci-dessous).
3. **Profil d'impact business** : pour chaque axe (opérationnel, légal, financier, image), le **maximum** des niveaux saisis sur les vulnérabilités ouvertes.

Le tableau de bord affiche également :

- Compteurs par **niveau de sévérité** (Aucun, Mineur, Important, Majeur, Critique) ;
- Compteurs par **phase** et par **statut de remédiation** ;
- Compteurs par **priorité** P1–P4.

### Test mixte v3.1 / v4.0

Un test est **mixte** quand ses vulnérabilités ouvertes sont notées pour certaines en CVSS v3.1 et pour d'autres en CVSS v4.0. Si toutes les vulnérabilités ouvertes utilisent la même version, les indicateurs ci-dessus s'appliquent sans changement.

Les scores numériques des deux versions ne sont pas comparables : la v4.0 n'a plus de portée et ajoute d'autres métriques. **Aucun calcul ni aucune comparaison ne mélange donc des scores v3.1 et v4.0** (maximum, moyenne, tri). Seuls les **niveaux** (Aucun → Critique) se comparent, car leurs seuils sont les mêmes dans les deux versions.

Dans un test mixte :

1. **Score de gravité technique** : le bandeau affiche le **niveau le plus élevé** parmi toutes les vulnérabilités ouvertes, puis le **maximum de chaque version séparément**, chacun avec son niveau. Exemple : « 🔴 Critique — v3.1 : 8,8 (Majeur) · v4.0 : 9,3 (Critique) ».
2. **Score agrégé optionnel** : une moyenne pondérée **par version**, chacune avec son nombre de vulnérabilités. Pour la version $v$, avec $p_i$ le poids de priorité ($P1 = 4$ … $P4 = 1$) et $s_i$ le score de base de la vulnérabilité $i$ :

$$\text{Moyenne}_v = \frac{\sum_{i \in v} p_i \times s_i}{\sum_{i \in v} p_i}$$

3. **Signalement** : un badge « Test mixte » accompagne le bandeau du tableau de bord et la synthèse des rapports exportés.
4. **Indicateurs inchangés** : le profil d'impact business, les compteurs (niveau, phase, statut de remédiation, priorité), la matrice sévérité × impact business et la suggestion de priorité P1–P4 reposent sur les niveaux ou les priorités ; ils restent communs aux deux versions.

Les rapports exportés suivent les mêmes règles ; chaque score cité y porte sa version.

### Graphiques

Les graphiques suivants sont générés automatiquement (exportables dans les rapports PDF/HTML/OpenDocument) :

- Répartition des vulnérabilités par niveau de sévérité (camembert ou barres) ;
- Répartition par phase du test ;
- Évolution du stock ouvert vs corrigé/vérifié dans le temps (si l'historique de remédiation est renseigné) ;
- Matrice sévérité × impact business (vue synthèse).

## Conclusions

Champ de **synthèse narrative** rédigé par le chef de projet ou le testeur désigné. Il doit couvrir :

- Le contexte et le périmètre réellement testé ;
- Les constats majeurs (en renvoyant aux vulnérabilités P1/P2) ;
- Les limites du test (exclusions, indisponibilités, 0-day hors périmètre) ;
- L'appréciation globale du niveau de maîtrise.

Un brouillon peut être prérempli à partir des compteurs et du score de gravité technique, puis **obligatoirement relu et validé** avant export du rapport.

### Mesures à apporter

Liste ordonnée des actions recommandées, **agrégée** depuis les [[11.09 Vulnérabilités et remédiation#Remédiation|fiches de remédiation]] (libellé, priorité, vulnérabilités liées). Le rédacteur peut :

- Réordonner, fusionner ou scinder des mesures ;
- Ajouter des mesures transverses absentes des fiches (gouvernance, sensibilisation, supervision).

Chaque mesure du rapport pointe vers une ou plusieurs vulnérabilités. Le catalogue n'est pas figé : pas de liste unique imposée, afin de rester atomique et contextualisé.

### Contre-mesures

Inventaire des **contrôles déjà en place** observés pendant le test (pare-feu, MFA, durcissement, supervision, sauvegardes, procédures). Pour chaque contre-mesure :

- Description ;
- Composants concernés ;
- Efficacité constatée (empêche, détecte, limite, contourné) ;
- Lien éventuel vers une vulnérabilité (contrôle insuffisant) ou vers une mesure (renforcement).

Ces éléments nourrissent le rapport pour distinguer ce qui existe déjà de ce qui reste à faire.
