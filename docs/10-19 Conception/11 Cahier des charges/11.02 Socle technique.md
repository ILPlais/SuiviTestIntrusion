# 11.02 Socle technique

## Versions

- **PHP** : [version **8.3**](https://www.php.net/downloads.php?version=8.3) ou supérieure ;
- **Laravel** : [version **11**](https://laravel.com/framework/docs/11.x/sanctum) ou supérieure (branche LTS au moment de l'implémentation) ;
- **Node.js** (outillage front / build de la SPA) : [version **20**](https://nodejs.org/docs/latest-v20.x/api/) ou supérieure.

## Licence, langues et accessibilité

Règles fixées par [[13.07 Licence, langues et accessibilité]] :

- **Licence** : MIT ; openpgp.js (LGPL) livré comme module séparé ; aucune dépendance GPL ou AGPL liée au code ; licences des dépendances contrôlées en CI ;
- **Langues** : français seul en V1, chaînes de l'interface (vue-i18n) et messages de l'API (fichiers de langue Laravel) traduisibles ; anglais en V2 ; pas de langue écrite de droite à gauche ;
- **Dates** : échangées en UTC (ISO 8601), affichées selon la langue dans le fuseau horaire du navigateur ;
- **Accessibilité** : bonnes pratiques en V1 (sémantique, clavier, contrastes, libellés, contrôles automatiques axe) ; conformité WCAG 2.2 AA en V2 ;
- **Affichage** : bureau et tablette (768 pixels de large au moins) en V1 ; smartphone en V2.

## Bases de données

Les bases de données utilisées dépendront de la quantité de données à administrer. Ce sera à l'utilisateur de choisir lors de la mise en place du serveur.

Les systèmes de bases de données utilisables seront :
- SQLite ;
- MySQL / MariaDB ;
- PostgreSQL.

Le compte utilisé par Laravel pour se connecter au SGBD est un **compte technique** défini à l'installation. Il ne constitue **pas** un mode d'authentification des utilisateurs métier (voir [[11.06 Gestion des utilisateurs]]).

## Déploiement

Deux modes sont supportés, au choix de l'exploitant :

- **Docker Compose** (recommandé) : services `app` (HTTP sur un réseau interne), `queue` (worker), `scheduler` (planificateur), `database` optionnelle, volume des preuves chiffrées. En V1, un proxy inverse externe, fourni par l'exploitant, termine le TLS ; un service web HTTPS intégré viendra en V2 ;
- **Installation manuelle** sur un hôte PHP (documentation pas-à-pas : PHP-FPM, file d'attente, cron, permissions du stockage).

## Infrastructure

Règles fixées par [[13.06 Infrastructure, e-mail et sécurité HTTP]] :

- **File d'attente** : pilote `database` (Redis possible par configuration), trois essais espacés, échecs signalés aux administrateurs ; planificateur Laravel pour les purges ;
- **E-mail** : aucun envoi en V1 ; invitations et liens de réinitialisation affichés chez l'administrateur, double authentification par TOTP, notifications dans l'application ;
- **TLS** : terminé par le proxy externe (TLS 1.2 au minimum, 1.3 privilégié), seul proxy de confiance pour Laravel ; HSTS envoyé par l'application ;
- **CORS** désactivé (même origine) ; cookie de session `Secure`, `HttpOnly`, `SameSite=Strict`, préfixe `__Host-`.

## Sauvegardes

La gestion des sauvegardes sera faite par [Portabase](https://portabase.io/).

Une sauvegarde **automatique** est paramétrable (fréquence par défaut : quotidienne) :

- Dump de la base (métadonnées, utilisateurs, trousseaux chiffrés) ;
- Copie du stockage des fichiers **déjà chiffrés** (pas de déchiffrement côté serveur) ;
- Horodatage, rétention paramétrable (défaut : 14 jours), journal du succès / échec.

Les archives de sauvegarde peuvent être chiffrées avec une clé d'exploitant distincte (GPG). La restauration est documentée et testable hors production.

## Journaux d'audit

Toute action sensible est consignée : auteur, horodatage, objet (test, vulnérabilité, document, utilisateur), action, résumé avant/après lorsque c'est pertinent. Les journaux d'audit ne contiennent **jamais** de secret en clair (mots de passe, CEK, clé privée). Conservation alignée sur la politique de rétention paramétrable.

Les événements audités incluent au minimum : connexions, cycle de vie des comptes (invitation, activation, désactivation, réactivation, suppression), changements d'ACL, partage/révocation de documents, transferts de propriété, demandes de rechiffrement au départ d'un utilisateur, exports, changements de statut de test ou de remédiation, validation client.
