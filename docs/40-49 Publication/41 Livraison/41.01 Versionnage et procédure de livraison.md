# 41.01 Versionnage et procédure de livraison

## Versionnage

Les versions suivent [SemVer](https://semver.org/lang/fr/) : `MAJEUR.MINEUR.CORRECTIF`.

- **MAJEUR** : changement incompatible de l'API `/api/v1/`, du format des preuves chiffrées ou de l'export JSON/XML.
- **MINEUR** : nouvelle fonctionnalité compatible.
- **CORRECTIF** : correction de bug.

Tant que la V1 n'est pas livrée, les versions restent en `0.x.y`.

## Procédure

1. Toutes les stories prévues pour la version sont à `done` et leurs branches intégrées à `main`.
2. Campagne de tests passée et consignée dans [[32.00 Index des campagnes]].
3. `CHANGELOG.md` (racine du dépôt) : la section « Non publié » devient la section de la version, datée.
4. Commit « Version X.Y.Z » sur `main`, puis étiquette Git `vX.Y.Z`.
5. Construction et publication des images Docker (`socle-2`).
6. Les fiches de retours corrigées passent au statut `publié`.
