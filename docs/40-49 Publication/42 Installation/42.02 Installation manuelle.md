# 42.02 Installation manuelle

Installation sans Docker sur un hôte Linux (Debian 12 ou Ubuntu 24.04 et suivantes), avec nginx et PHP-FPM ([[11.02 Socle technique]]). L'installation recommandée reste [[42.01 Installation avec Docker Compose]] ; les règles d'infrastructure viennent de [[13.06 Infrastructure, e-mail et sécurité HTTP]].

Ici, nginx termine le TLS et appelle PHP-FPM directement : il n'y a pas de proxy inverse devant l'application, et `TRUSTED_PROXIES` reste vide. Si un autre proxy est placé devant nginx, déclarer son adresse dans `TRUSTED_PROXIES` (voir 42.01, « Proxy inverse »).

## Prérequis

| **Composant** | **Version** |
| --- | --- |
| PHP (FPM et CLI) | 8.3 ou plus, extensions `bcmath`, `ctype`, `curl`, `dom`, `fileinfo`, `intl`, `mbstring`, `openssl`, `pdo`, `tokenizer`, `xml`, `zip` et le pilote PDO de la base (`pdo_sqlite`, `pdo_mysql` ou `pdo_pgsql`) |
| Composer | 2 |
| Node.js | 22, pour compiler la SPA (inutile ensuite sur le serveur) |
| nginx | 1.25.1 ou plus (directive `http2`) |
| Base | SQLite 3.35+, MySQL 8, MariaDB 10.11+ ou PostgreSQL 15+ |

Exemple sur Debian ou Ubuntu (PHP de la distribution, à adapter à la version disponible) :

```bash
sudo apt install --yes nginx php-fpm php-cli php-bcmath php-curl php-intl php-mbstring php-xml php-zip php-sqlite3 unzip git
```

## Étapes

Dans la suite, l'application est installée dans `/var/www/suivi`, PHP-FPM et nginx tournent sous `www-data`, et `<instance>` désigne le nom public (par exemple `pentest.example.org`).

### 1. Code et dépendances

```bash
sudo mkdir --parents /var/www/suivi
sudo chown "$USER": /var/www/suivi
git clone https://github.com/ILPlais/SuiviTestIntrusion.git /var/www/suivi
cd /var/www/suivi/backend
composer install --no-dev --no-interaction --optimize-autoloader
```

### 2. SPA compilée

La SPA est servie par Laravel, sur la même origine que l'API : son build est copié dans `backend/public/`. La compilation peut se faire sur une autre machine, puis seul le contenu de `frontend/dist/` est copié.

```bash
cd /var/www/suivi/frontend
npm ci --no-fund --no-audit
npm run build
cp --recursive dist/. ../backend/public/
```

### 3. Configuration

```bash
cd /var/www/suivi/backend
cp .env.example .env
chmod 640 .env
php artisan key:generate --no-interaction
```

Régler dans `.env` :

```ini
APP_ENV=production
APP_DEBUG=false
APP_URL=https://<instance>
LOG_LEVEL=info
TRUSTED_PROXIES=
```

puis la base :

- **SQLite** : `DB_CONNECTION=sqlite`, `DB_DATABASE=/var/www/suivi/backend/database/database.sqlite`, `DB_BUSY_TIMEOUT=5000` et `DB_JOURNAL_MODE=wal` (le worker et le planificateur écrivent en même temps que le site) ; créer le fichier avec `touch database/database.sqlite` ;
- **MySQL, MariaDB ou PostgreSQL** : décommenter le bloc correspondant de `.env` et créer au préalable la base et son utilisateur.

`APP_KEY` chiffre les sessions et les cookies : elle se conserve avec les sauvegardes.

### 4. Droits sur les fichiers

Le code appartient au compte d'installation ; seuls `storage/`, `bootstrap/cache/` et, avec SQLite, `database/` sont inscriptibles par PHP.

```bash
cd /var/www/suivi/backend
sudo chown --recursive "$USER":www-data .
sudo chmod --recursive u=rwX,g=rX,o= .
sudo chown --recursive www-data:www-data storage bootstrap/cache
sudo chmod --recursive u=rwX,g=rwX,o= storage bootstrap/cache
# Avec SQLite seulement : la base et son dossier (fichiers -wal et -shm).
sudo chown www-data:www-data database database/database.sqlite
```

Les preuves chiffrées sont stockées sous `storage/app/private/` : jamais dans `public/`.

### 5. Base et caches

```bash
sudo --user=www-data php artisan migrate --force --no-interaction
sudo --user=www-data php artisan optimize --no-interaction
```

`php artisan optimize` est à relancer après chaque modification de `.env` ou mise à jour du code.

### 6. PHP-FPM

Créer `/etc/php/8.3/fpm/conf.d/99-suivi.ini` (adapter la version) pour aligner les limites de taille sur la GED (100 Mio par fichier, plus le surcoût du chiffrement) :

```ini
upload_max_filesize = 110M
post_max_size = 110M
memory_limit = 256M
expose_php = Off
date.timezone = UTC
```

puis `sudo systemctl restart php8.3-fpm`.

### 7. nginx

`/etc/nginx/sites-available/suivi` (TLS selon les exigences de 13.06, mêmes suites que `docker/proxy/nginx.conf.example`) :

```nginx
server {
	listen 80;
	listen [::]:80;
	server_name <instance>;
	return 301 https://$host$request_uri;
}

server {
	listen 443 ssl;
	listen [::]:443 ssl;
	http2 on;
	server_name <instance>;

	ssl_certificate /etc/ssl/suivi/fullchain.pem;
	ssl_certificate_key /etc/ssl/suivi/privkey.pem;
	ssl_protocols TLSv1.2 TLSv1.3;
	ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384:DHE-RSA-CHACHA20-POLY1305;
	ssl_prefer_server_ciphers off;
	ssl_session_timeout 1d;
	ssl_session_cache shared:SuiviSSL:10m;
	ssl_session_tickets off;

	root /var/www/suivi/backend/public;
	index index.php;
	client_max_body_size 110m;
	server_tokens off;

	# Fichiers de la SPA servis tels quels ; tout le reste passe par Laravel.
	location / {
		try_files $uri /index.php?$query_string;
	}

	# Ressources compilées : leur nom porte une empreinte.
	location /assets/ {
		expires max;
		add_header Cache-Control "public, immutable";
	}

	location = /index.php {
		include fastcgi_params;
		fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
		fastcgi_param DOCUMENT_ROOT $realpath_root;
		fastcgi_pass unix:/run/php/php8.3-fpm.sock;
		fastcgi_read_timeout 300s;
	}

	# Aucun autre script PHP n'est exécutable.
	location ~ \.php$ {
		return 404;
	}

	location ~ /\.(?!well-known) {
		deny all;
	}
}
```

```bash
sudo ln --symbolic /etc/nginx/sites-available/suivi /etc/nginx/sites-enabled/suivi
sudo nginx -t && sudo systemctl reload nginx
```

`fastcgi_params` transmet `HTTPS=on` : Laravel sait que la connexion est chiffrée sans proxy de confiance.

### 8. File d'attente (systemd)

`/etc/systemd/system/suivi-queue.service` :

```ini
[Unit]
Description=SuiviTestIntrusion : file d'attente
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/suivi/backend
ExecStart=/usr/bin/php artisan queue:work --tries=3 --backoff=10,60,300
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now suivi-queue
```

Après trois échecs, un job passe dans `failed_jobs` (`php artisan queue:failed`, puis `queue:retry <id>`).

### 9. Planificateur (cron)

`/etc/cron.d/suivi` :

```cron
* * * * * www-data cd /var/www/suivi/backend && php artisan schedule:run >> /dev/null 2>&1
```

### 10. Vérification

```bash
curl --fail https://<instance>/api/v1/health
systemctl status suivi-queue
```

La racine de l'instance affiche la SPA ; `/api/v1/health` répond `{"status":"ok","database":"ok", …}`.

## Mise à jour

```bash
cd /var/www/suivi
sudo --user=www-data php backend/artisan down
git pull
(cd backend && composer install --no-dev --no-interaction --optimize-autoloader)
(cd frontend && npm ci --no-fund --no-audit && npm run build && cp --recursive dist/. ../backend/public/)
cd backend
sudo --user=www-data php artisan migrate --force --no-interaction
sudo --user=www-data php artisan optimize --no-interaction
sudo systemctl restart php8.3-fpm suivi-queue
sudo --user=www-data php artisan up
```

## Sauvegardes

À sauvegarder ensemble : la base (fichier SQLite, après arrêt du site et du worker, ou `pg_dump` / `mysqldump`), le dossier `backend/storage/app/` (preuves chiffrées) et `backend/.env` (`APP_KEY`).
