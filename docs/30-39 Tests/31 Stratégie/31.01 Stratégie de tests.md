# 31.01 Stratégie de tests

## Niveaux de tests

| **Niveau**        | **Outil prévu**         | **Emplacement**                  |
| ----------------- | ----------------------- | -------------------------------- |
| Unitaires serveur | Pest / PHPUnit          | `backend/tests/Unit/`            |
| Fonctionnels API  | Pest / PHPUnit          | `backend/tests/Feature/`         |
| Unitaires client  | Vitest                  | `frontend/tests/unit/`           |
| Bout en bout      | Playwright              | `frontend/tests/e2e/`            |
| Sécurité          | Analyse statique, audit | CI (`socle-3`, `exploitation-5`) |

Les outils sont confirmés par la story `socle-3` (CI et outillage de tests).

## Campagnes de tests

Une campagne regroupe les tests manuels et les vérifications faites avant une publication.

- Un compte rendu par campagne : `32.xx Campagne vX.Y.Z.md`, référencé dans [[32.00 Index des campagnes]].
- Partir du modèle [[01.04 Modèle campagne de tests]].
- Chaque anomalie trouvée devient une fiche de bug `52.xx` (voir [[51.01 Traitement des retours]]).
